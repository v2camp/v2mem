# 设计：v2mem 同义词词库（起步配置 + 查询期展开 + 有效迭代 + 初始化 agent 提取）

- 日期：2026-09-17
- 状态：草案待复核
- 关联：docs/design-write-governance.md、docs/design-harness-memory-replace.md、docs/design-vector-cost.md

## 1. 目标与边界

为 v2mem 关键词检索补"同义不同词"缺口（如"日志怎么搬" vs 库内"ingest 机械化搬运"），**不引入语义向量模型**、守住 README 卖点（11MB 单文件、零外部服务、零长驻）。

- **起步小**：通用最小种子 + 用户可编辑文件，不做大而全通用词库（通用中文同义词库数 MB~数十 MB 且领域盲，已知错配）。
- **迭代靠数据闭环**：加词不是"想到就加"，而是被"是否带来净收益"的 eval 判据决定。
- **初始化可让 agent 提取**：抛开预装基础库，让宿主 agent 从记忆/specs/plans 提取项目域词库；提取方法先研究、证据驱动、交给精确判据收敛。

## 2. 词库形态与文件格式

纯文本、用户可编辑、放库同目录，`--synonyms` 可覆盖路径：

```text
# 通用内置种子（语言中性，不绑任何工具领域）——整行注释；行首 ! 显式停用
检索 = find, search, 查找, 查询, 搜, lookup
入库 = import, ingest, 导入, 搬进, load
删除 = delete, remove, 移除, 清除

[v2mem]                 # 工程作用域段，只影响 v2mem 项目
harness = 原生记忆, 工具记忆, 宿主, 钩子宿主

[training-products]
导入 = ingest, 灌库, bulk
```

- **归一方向**：等号左边是标准词（归一目标），右边是候选别名；展开只把"查询里的别名"映射到"标准词"，**单向**，可预测可审计。
- **作用域**：全局段 + `[project]` 段；工程词只在该工程生效，避免某领域带歪全局。
- **种子**：内置种子仅"语言中性"词（检索/入库/删除），显式区分"项目域"和"全局语言中性"两层；工具特有词绝不内置。

## 3. 查询期展开机制

在 `queryExpr` 之前把用户词做同义词展开（扩展为标准词 + 保留原词），再拼 FTS 表达式：

- 展开后的词仍走既有**词间 OR / 词组内 AND** 规则，顺带与多关键词交并集语义衔接。
- **不动索引、不改 content_hash**：展开只在查询期，检索结果无副作用。
- 开关：`MEM_SYN_DICT=0` 整个关闭，回退到无词库检索，保证可回退。

## 4. 有效迭代闭环（用户侧如何"有效"迭代）

孤立盲加最容易坏——同义词抬 Recall 却压 MRR。故迭代绑 eval：

1. **诊断**：`mem search --explain "检索有问题吗"` 输出 top-N 命中 + 词面覆盖，标出"用户问的哪个词 ↔ 库里标准词 没对上"——这是"该补哪条词"的直接证据。
2. **回归**：用户在 `gold/` 补"真实查询 → 应命中记忆"，跑 `mem eval recall --gold-dir gold`。
3. **判据（净赚才保留）**：新增同义词后要求 **Recall↑ 且 MRR 不↓** 才保留；纯升 Recall 但 MRR 明显回退 → 告警建议回退。
4. **僵尸清理**：长期未被任何真实查询/gold 触发的同义词，标记提示可清理（加进去却没帮上 recall ⇒ 冗余或误导）。
5. **跨设备**：`synonyms.txt` 随现有 `mem sync`（git）跨设备归并，A 设备补的词 B 设备 pull 即得；产物本身也进 eval 门禁回测，词库增长不偷偷破坏检索。

## 5. 初始化时的 agent 辅助提取（研究部分）

目标：`mem init` / 新命令 `mem lexicon init --scan <project>` 时，让宿主 agent 借助记忆系统、specs、plans 等**自动提取项目域同义词**，高效且准确。

### 5.1 为什么不能用"跑一遍通用抽取"

静态分词/词频只会得到高频词，**不会得到"哪两个词是同一概念"**；通用同义词库领域盲。所以要**证据驱动**：只认可"系统自身行为上等价"的词对。

### 5.2 提取管线（四步）

**Step A 候选词采集（召回侧）**：扫描输入（Level-1 记忆、README、AGENTS、docs/、spec、plans、记忆表内容），做 N-gram 词频；滤掉停用词、滤掉已在基础库的词，保留领域高频词作候选。

**Step B 同义候选生成（用既有检索当"行为 oracle"）**：对候选词 X，取"以 X 检索、命中集 J(X)"；若另一词 Y 的命中集 J(Y) 与 J(X) **高度重叠**（Jaccard 高），则 (X,Y) 是**行为同义**候选——同一个查询换了词面后鼠标还捞到同一批记忆。这一步零外部模型、自含、便宜。

**Step C 精度治理（收敛）**：候选对必须过"净收益判据"——加入后 `mem eval recall --gold-dir` 应 **Recall↑ 且 MRR 不↓**；判据不过的进**人工复核清单**而非自动采纳；作用域限定 `[project]` 段防带偏全局。

**Step D 输出**：把通过判据的对写入 `synonyms.txt` 的 `[<project>]` 段。

### 5.3 精度风险与对策

| 风险 | 对策 |
|---|---|
| 通用高频词误判同义（"日志"vs"记录"被合） | 命中集重叠 + 净收益判据双重把关；权重惩罚"跨概念"高频词 |
| 假如词表膨胀 | 僵尸清理 + `[project]` 作用域 + 每个对都留证据（触发它的查询） |
| agent 提出错配对 | 绝不自动采纳不确定项 → 进复核清单，由净收益/人工决定 |
| 与向量路线并存？ | 词库是零空间的短期增益；向量是后续重投入。词库展开与向量检索不冲突，可作为向量之前的基线 |

### 5.4 提取参数校准（已实验，`go test -tags calib -run Calib ./internal/store/`）

用「已知同义簇(3 簇×5 词) + 术语清单式标准记忆 + 15 条干扰记忆 + 高频泛词」的合成语料，
以 `store.Search` 当行为 oracle，扫描 命中集相似度指标 × top-k × 阈值，度量 P/R/F1：

| 指标 | k | 阈值 | P | R | F1 |
|---|---|---|---|---|---|
| Jaccard | 3 | 0.3 | 86.7% | 86.7% | **86.7%** |
| Jaccard | 5/8 | 0.3 | 81.2% | 86.7% | 83.9% |
| Jaccard | 5/8 | 0.5 | **95.0%** | 63.3% | 76.0% |
| containment | 3~8 | 任意 | ≤61.9%(P) | 86.7~100% | ≤72.2% |

**结论与默认参数（决策依据）：**
1. **指标用 Jaccard，弃 containment**：containment 对大小不对称命中集过宽容，高频泛词大量混入，P 上不去（封顶 ~62%）；Jaccard 在 0.5 可达 95% P。
2. **top-k 取值 5~8，阈值 ≤0.5**：小 top-k（k=3）把命中集压到 1~2 条，Jaccard 上界只有 ~0.5，阈值 >0.5 恒为 0（NaN 退化）——所以**阈值上限就是 0.5**，再高无意义。
3. **默认阈值 θ=0.5（精度优先）**：P=95%、R=63%。与「默认进复核清单、不确定不强采纳」的设计一致——错同义会**主动伤精度**，漏召回可用更大 k / 复核清单兜住。
4. **高频泛词**（用于/文件/记忆/词/内容等）确实制造假同义，但 **Jaccard×θ=0.5 已把假同义压到 1 个**（k=8 时 fp=1）；另加一道**命中集广度护栏**：候选词命中记忆数 > 库内 30% 视为泛词/歧义词，不参与配对（稳健）。
5. N-gram 窗口与候选规模上限：随超大规模库的回归再调，首版默认候选=记忆正文中出现 ≥2 次的 2-gram/词。

实现时以 `internal/store` 的 `calibrate_test.go`（`//go:build calib`）为可复跑校准基线；参数改默认值前先重跑覆盖。

### 5.5 命令参考（`mem lexicon init`）

```text
mem lexicon init --project <X> [--terms "词A,词B"]   # 主路径：真实查询词，精度高（校准即此路径）
                 [--auto] [--min-freq N]            # 实验性：从记忆正文提 bigram 作候选，须跨 ≥2 条记忆
                 [--threshold F] [--k N]            # 默认 θ=0.5、k=8（§5.4；阈值上限 0.5）
                 [--out <path>]                     # 默认 <库目录>/synonyms.txt
                 [--dry-run]                        # 只预览聚簇与复核清单，不写文件
```

- 候选词二选一：`--terms`（用户在 `gold/audit` 或手工给出的真实查询词）或 `--auto`（bigram 提取，跨 ≥2 条不同记忆才保留）。
- 泛词护栏：库内记忆 ≥20 条时启用，命中记忆 > 库总量 30% 的候选不参与配对。
- 输出：把聚簇里「已存在的别名」去重后追加到 `synonyms.txt` 的 `[<project>]` 段；`[0.40, θ)` 区间的词对列入复核清单而**不强采纳**。

## 6. 落地分期

- **一期（已完成）**：`synonyms.txt` 解析 + 查询期展开 + `MEM_SYN_DICT` 开关 + `--explain` 诊断 + 检索集成 + 测试。
- **二期（本设计，参数已校准）**：`mem lexicon init --project <X>` 提取管线（Step A-D，用 §5.4 默认值）+ agent 复核清单 + 僵尸清理。
- **三期（§8）**：自动维护闭环 —— LLM 提取（agent 扫增量资产）+ 试用期回测 + 反馈沉淀 + 衰减清理，惰性触发。

## 7. 测试与验收

- 展开：给定 synonyms.txt，断言 `search "别名词"` 能命中"标准词"记忆；`MEM_SYN_DICT=0` 回退。
- 作用域：`[project]` 词仅该工程命中。
- 判据：构造 gold，断言"Recall↑ 且 MRR 不↓"通过/不通过行为。
- 回归：跑既有 `mem eval recall` 确认引入词库不破坏现有基准。

## 8. 自动维护闭环（LLM 提取 × 试用期回测 合并路线）

§4 的闭环靠用户手动跑 `--explain`/`mem eval` 驱动；本节的路线把它自动化：
**LLM 提取闭环**负责发现（召回侧），**试用期回测**负责决策（精度侧），两者合并为一个
**词条生命周期状态机**，由统一的惰性触发机制驱动，全程反馈沉淀回写、驱动下轮提取。

### 8.1 分工：谁管召回、谁管精度

| 侧 | 承担者 | 依据 |
|:---|:---|:---|
| 发现（召回） | LLM 扫描增量资产 | 静态 bigram 不知"哪两个词同概念"（§5.1）；LLM 零样本阅读，不需要训练样本 |
| 预检（候选过滤） | 行为 oracle | 复用 §5.2 Step B + §5.4 默认参数（Jaccard θ=0.5、泛词护栏） |
| 决策（净收益） | 试用期回测 | §4 判据"Recall↑ 且 MRR 不↓"的自动化版本 |
| 退出（生命周期） | 衰减打分 | §4.4 僵尸清理的自动化版本（ACT-R 式：命中次数 + 最近命中） |
| 记忆（经验回写） | 反馈沉淀 | 确认/撤回/清理回写状态表 → 下轮提取的 few-shot + 黑名单 |

### 8.2 词条生命周期状态机

```
candidate ──预检通过──▶ trial ──回测达标──▶ stable（查询期自动展开）
              │                │
              └─复核不通过──▶ reverted ────────┐
                             stable ──久未命中──▶ zombie ──确认──▶ removed
                                        （30 天待复查 / 90 天可删）
   所有决策落定 ────────────▶ 反馈沉淀 ──▶ 下轮 candidate（few-shot + 黑名单）
```

- `trial → stable`：N 次真实查询后 ΔMRR 不↓。
- `trial → reverted`：ΔMRR 明显回退即撤回（绝不自动保留不确定项，§5.3）。
- `reverted` 后进入黑名单冷却期，避免反复横跳。

### 8.3 词条状态字段

```text
word | standard | status(candidate/trial/stable/reverted/zombie/removed)
source(llm|auto|terms) | confidence | reason          # LLM 提取的来源与置信理由
trials | hit_count | mrr_delta | last_hit_at | updated_at  # 回测与衰减输入
```

### 8.4 触发机制：惰性 + 借道（无守护进程）

v2mem 零常驻进程，mem 不会自己醒来。触发原则：
**一切维护借道已有事件，只做轻量动作；重动作（LLM 提取、深度回测）排队给 agent/维护命令执行。**

| 阶段 | 触发事件 | 借道点 | 动作（必须轻量） |
|:---|:---|:---|:---|
| 候选标记 | hook session-start / prompt-submit | 读路径 | 算资产指纹（AGENTS/README/docs/** 的 mtime+size 摘要），与上次比对，变了→写 pending 标记 |
| LLM 提取 | agent 看到注入提示后主动执行 | `mem lexicon init --terms` | 扫资产产候选（不自动执行，只提示） |
| 行为预检 | `mem lexicon init` | 同上 | Jaccard ≥0.5 + 泛词护栏 → 候选进 trial |
| 试用累积 | 每次查询命中 trial 词 | search + hook prompt-submit | 累加 trials/hit_count（UPDATE，微秒级） |
| 试用结算 | 维护命令或 session-end | `mem gc` / `mem audit` / hook session-end | 批量 settle：ΔMRR 不↓→stable，↓→reverted |
| 僵尸衰减 | 维护命令 | `mem gc`（已有 TTL 锚点） | 衰减打分 → 待清理清单 |
| 反馈沉淀 | 每层决策落定 | 各层收尾 | 回写状态表 |

**统一锚点 = hook 生命周期**：session-start（指纹检测 + 首次判断 + 注入提示）、
prompt-submit（试用累积）、session-end（结算 + 衰减刷新）。
hook 是唯一"每次会话必发生"的确定性事件，"用户启动会话"即维护时机；
主动维护命令（gc / lexicon init / audit）做深维护。

### 8.5 首次使用冷启动

- 状态文件 `.mem/lexicon_state.json` 不存在 → 判定首次使用 → 全量资产视为待提取。
- 首次 hook 激活时注入提示 agent："检测到 N 份资产（AGENTS.md、docs/…），建议运行
  `mem lexicon init --project <X>` 提取项目域同义词。"
- 此后每次 hook 只比对增量差异，不再全量提示。

### 8.6 防打扰设计

- **按批次去重**：pending 标记带资产指纹，指纹没变不重复提示（注入给 `lexicon_pending: false`）。
- **注入预算**：提示只占注入一行，不挤占记忆注入额度。
- **结算收敛**：trial 词每 N 次查询只结算一次；reverted 进黑名单冷却期。

### 8.7 落地分期

- **阶段 1 自动候选**：agent 扫资产 → `mem lexicon init --terms` 消费 + 引入词条状态表（先接上"LLM 提取 + 沉淀"半环，不动检索内核）。
- **阶段 2 试用回测**：trial 词在 audit 真实查询里累计 ΔMRR，N 次后自动 settle；这是唯一"自动写库"点。
- **阶段 3 僵尸清理**：衰减打分 → 复核确认 → 移除回写，复用 `mem gc` 的备份纪律。

### 8.8 验收标准

- 状态机：给定状态序列，断言 candidate→trial→stable / reverted、stable→zombie→removed 转换正确。
- 触发：hook 事件驱动下，指纹变更产生一次 pending 标记，且幂等（重复触发不重复提示）。
- 回测：构造 gold，断言"试用后 ΔMRR 不↓ 才转 stable；↓ 则撤回"。
- 回归：确认自动维护不破坏 §7 既有一期/二期行为（`mem eval recall` 基准不降）。
