# v2mem 价值主张

> **定位**：本文件回答「**为什么**」，不回答「怎么做」。`README.md` 面向使用者讲是什么、怎么用；
> `docs/DESIGN.md` 与 `docs/design-*.md` 面向实现讲怎么做；本文件是三者之上的**战略锚点**。
> **读者**：项目所有者 + 未来的 agent。**用途**：判断「下一步做什么、不做什么」，
> 并在新认识与旧表述冲突时**裁决**。
> **范围**：四条价值主张（超限治理 / 检索与资产索引 / 跨机器覆盖 / 智能层）按三节组织——
> 前两条合成「纵向 · 索引链」，后两条各成一节。每条写明**现状、前提、判据**；
> 未来项只写价值假设与判据，不写实现形态。

---

## 0. 一句话主张

> 注入的上下文**恒定极小**，能取到的细节**无限深**——靠一条 `类码 → 记忆 → 项目资产`
> 的**可导航索引链**，且这条链在多项目、多设备间是**同一条**。

三个分句各管一段：**主张**（极小 / 无限深）、**手段**（索引链）、**范围**（多项目多设备）。

**与 README 的关系**：README 的命题「文件不再接收细节的那一刻，截断与压缩需求就消失了」
是本主张**第 1 分句的一个推论**，而非全部。本文件**包含并扩展**它，不推翻它。

本主张是全文的**判据**：任何设计取舍，都对这三个分句加分或减分。加分不了、也减分不了的
改动，与价值主张无关——可以做，但优先级应让位于能加分的改动。

## 1. 纵向 · 索引链（点 1 + 点 2）

### 1.1 三跳，以及每跳消灭的猜测

价值不在于「存了多少记忆」，而在于**每一跳都替 Agent 消灭了一种猜测**。

| 跳 | 载体 | 进上下文 | 消灭的猜测 | 现状 |
|:---|:---|:---|:---|:---|
| ① 类码 | L1 会话级文件 | ✅ 常数 | 「**该不该查**」 | 待把现有「钩子」升级为类码表 |
| ② 记忆 | `~/.v2mem/mem.db` | ❌ 按需 | 「**我记得对不对**」 | 已落地（FTS5 + bm25 + 同义词展开） |
| ③ 资产 | `provenance` 字段 | ❌ 按需 | 「**这条记忆还成立吗**」 | **写侧有、读侧无**（见 1.3） |

「项目 memory 文件 → mem → 项目资产」是两跳**索引**、三级**载体**。这就是「两级索引」的确切含义。

### 1.2 类码表：`kind` 的短别名，不是第二套分类

L1 文件里的「记忆钩子」升级为一张**类码表**：

| 类码 | `kind` | L1 里写的触发条件 |
|:---|:---|:---|
| `P` | `preference` | 涉及用户 / 项目偏好、默认选择、禁用做法时 |
| `D` | `decision` | 要复述「为什么这么定」时 |
| `X` | `pitfall` | 遇到报错、反常现象、曾被坑过的路径时 |
| `T` | `task` | 要确认「上次做到哪 / 还剩什么」时 |

> `kind` **没有白名单校验**。实际在用的取值除上表四项外，还有 `fact`（入库默认）与
> `rule`（硬规则标记）。`rule` 走的是 L1 的**另一条通道**——`mem notes` / `mem hook`
> 把它抽成「硬规则」小字条，与类码表**并列而不冲突**：硬规则管「不能做什么」，
> 类码表管「什么时候该去查」。

三条纪律：

1. **类码只是 `kind` 的别名**，真理源仍是库里的 `kind` 字段。不新增表、不新增列、
   不改 schema、不改门禁——避免分类体系漂移。
2. **不列举 `fact`**。`fact` 是入库默认值（见 `cmd/mem/main.go` 的 `--kind` 说明），
   它写不出「什么时候该查」的触发条件；放进 L1 只会稀释信号。命中四类触发条件即**必须**查，
   其余走自由检索。
3. **L1 硬约束不变**（≤ 2KB / 40 行）。类码表 4 行是**常数**，不随记忆条数增长——
   这正是它区别于「条级编码表」的地方（条级编码表会随记忆量膨胀，等于把超限问题
   从内容搬到索引上）。

### 1.3 二级索引「只指向、不判定」

现状核实：`provenance`（`{file, line, source, preview}`）**仅由 `mem ingest` 写入**
（`cmd/mem/level1.go`），并经 `mem sync` 传播；**没有任何读侧入口**。
即：这一跳目前是**半条路**——能写进去，取不出来。

本期补齐的方向是**以资产为入口的反查**：`mem asset <path>` ——
语义严格限定为「**列出关于这个文件我知道什么**」。

明确**不做**：

- 不比对文件 hash、不自动标记失效（那是 `docs/design-provenance.md` §6 的「失效联动」，
  需引入指纹存储 + 扫描，成本高一个量级）
- 不替 Agent 判断「这条记忆过期了没」

理由是**架构性的**，不是省事：一旦这级索引承担判定，它就必须准确；而准确需要语义模型，
模型进关键路径会直接摧毁检索 ~9ms 的前提。**判定留给 Agent**——它拿到 `file:line` 后
自己去读一眼源文件，这恰恰是第 ③ 跳的价值所在。

### 1.4 资产边界（本期）

只到**文件**一级：`provenance.file`（相对工程根）+ `line` + `preview`。

不含：git commit、文档章节锚点、会话 id、外部 URL。理由：这些来源**当前没有写入路径**，
先不建空索引——空索引会被误当成「索引里没有 = 不存在」。

## 2. 横向 · 覆盖（点 3）

**价值**：两台机器对同一项目的记忆**汇到一处、可一起看**——减少「换个机器就得重新交代一遍」的代价。
带来的是记忆的**整体性**：完整性从「单机单项目」扩到「全部机器 × 全部项目」。

**机制现状（三层去重）**

| 层 | 时机 | 判据 |
|:---|:---|:---|
| 写入期 | `mem add` | `content_hash` 唯一索引 `(content_hash, project)` |
| 维护期 | `mem consolidate` | 字符 3-gram MinHash 估 Jaccard，同 `project` 内聚簇 |
| 跨设备期 | `mem sync` / `export` / `import` | 按 `(content_hash, project)` 归并，`content_hash + updated_at` 最近者胜，**冲突并存打标记** |

**必须写明的前提（否则是空头承诺）**：正确的表述**不是**「两台机器的记忆自动合成一份」，
而是「**汇到一处、可一起看**；真正合并发生在写入规范 + 保守归并都满足时，
其余情况**并存并标记冲突**」。

归并天然保守有实测依据：`docs/design-dedup-merge.md` 记录过 `CGO_ENABLED=0` 与 `=1`
两条**互斥规则**相似度高达 0.906——只卡阈值会把它们合成一条。所以护栏优先于阈值，
取向是**宁并存不误合**：误合丢信息不可逆，并存多一条可人工消解。

**为什么这属于「横向」**：它不增加单库内的记忆深度，只扩展**覆盖**。
所以它与第 1 节**并列**，不是第 1 节的下一步。

## 3. 智能层（点 4，未来）

三项一律写「**价值假设 / 成立前提 / 可验证判据**」。判据的要求是：**能判死这一项**。

### 3.1 记忆加工

- **价值假设**：从「取回事实」升级到「取回结论」——N 条散记忆压成 1 条带判断的洞察，
  减少 Agent 每次重新推导的轮次。
- **成立前提**：① 库内同主题密度足够，否则无料可加工；② 产出必须能与**原始观察**区分——
  原始是**证据**，加工是**推论**。
- **判据**：加工条目被命中后，**同一会话内的追问轮次下降**（用 `~/.v2mem/audit.jsonl`
  的查询序列，与未命中基线对比）；或人工抽查「比单条原始记忆更有用」的比例过阈。
- **边界**：加工产出**只许新增条目**（走 `derived_from` 边），**不得覆盖**原始记忆。
  前置工作：`edges` 表当前是**空壳**——schema 已建、`rel` 约定含 `derived_from`，
  但全仓库无任何读写路径，要落地得先接上写入与遍历。

### 3.2 deeplink 跳转

- **价值假设**：从「读到一条记忆」到「回到它产生的现场」（会话 / 源文件那一行），
  省掉人工翻找。
- **成立前提（生死线）**：**各 harness 是否暴露可跳转的会话地址，目前完全未验证**。
  在用工具的会话标识各不相同，能否构造可跳转链接未知。
- **判据**：先做一次**可行性验证**（不是实现）——若有 ≥ 2 个在用工具能构造出可跳转链接，
  则立项；否则**降级为「复制路径 + 会话 id」或直接砍掉**。

写判据的意义正在于此：让一项愿景**可以被判死**，而不是永远挂在路线图上。

### 3.3 夜间「梦」

- **价值假设**：Agent 不只在被问时取回，还能在无人时沿**用户的价值指向**主动做深度总结
  与探索，产出「下一次对话可能用得上」的东西。
- **成立前提（两个未决，立项前必须裁决）**：
  - **(a)「价值指向」从哪来** —— 必须显式给出输入源，否则梦无方向。候选：
    `kind=rule` 与高 salience 的全局记忆、Obsidian 知识库的 OKR、近期 `audit.jsonl`
    的高频查询主题。
  - **(b) 产出落哪** —— 直接回写主库即污染：**梦是推测，不是观察**。
- **建议形态（记为待裁决的建议，不作为形态规范）**：产出进**隔离区**——独立 scope 或
  新增 `kind=insight`（后者需扩展 `kind` 枚举，与 §1.2「不动 schema」冲突，故优先独立 scope）；
  **默认不进检索**，需显式「采纳」才升格为普通记忆。
- **判据**：产出**采纳率**（人读后保留的比例）。若长期趋近 0，说明「价值指向」前提不成立，
  **停掉**——不要无限期维护一个自我欣赏的循环。

## 4. 红线（不做什么）

| 红线 | 来源 | 理由 |
|:---|:---|:---|
| 钩子绝不阻断宿主 | 已有 | 记忆系统出问题不该中断用户会话 |
| 不做云服务 / 常驻进程 | 已有 | 轻量是它的第一性差异 |
| 向量不进检索关键路径 | 已有 | 保住 ~9ms 的检索前提 |
| L1 不接收具体记忆条目 | 已有 | 文件一接收细节，截断与压缩立刻复发 |
| **二级索引只指向、不判定** | **新增** | 判定需要语义，语义进关键路径即违约 |
| **梦的产出不回写主库** | **新增** | 推测污染观察，且不可逆 |

后两条是本次价值主张探讨的**新增产出**——它们无法从代码里读出来，只能由本文件承载。
