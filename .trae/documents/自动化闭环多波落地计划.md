# 自动化闭环多波落地计划（建议 1–5）

## Summary

按上一轮评估的建议顺序，分批把“自动化闭环”从「机制已建、生产未闭环」推进到「可灰度、可度量、可收尾」：

1. 波 1（并行 4 个子代理）：`maintain` 接入 model-auto 自动裁决、`memories.scope` 写入、`eval flow` legacy/prod 剖面、生产积压只读诊断。
2. 波 2（并行 3 个子代理）：`maintain --stage` 全阶段（proposal/adjudicate/consolidate/gc）、detach 存活验证、transcript cursor 终态回收。
3. 波 3（单子代理）：CLI 命令面收编（低风险删除 + 弃用标记），在波 2 合入后做，避免命令/实现双改冲突。
4. 波 4（主控）：受控灰度验证、真实库只读指标复核、验收文档分册、全量门禁与合入清理。

**本轮范围**：建议 1–5；**P4（Judge 扩权）不在本轮**，只保留前置项清单。
**生产变更纪律**：受控灰度。子代理不得写 `~/.v2mem`、不得改 hooks/model.json、不得在生产库跑 `maintain`；只允许只读查询、临时 HOME/临时库，以及带 `content/` 的生产库副本。

2. **波 2 合入后**：在副本上跑 `mem maintain --stage=all --dry-run` 与一次真实 `--stage=all`（临时库），确认顺序、零写、GC 引用保护。
3. **波 3 合入后**：确认命令面数量与替代路径；`make test`/`cover-gate`/`test-faults`/`test-e2e` 全绿。
4. **验收文档**：
   - 新建 `docs/acceptance-automation.md`（≤300 行），记录本轮每个任务的命令、输出、指标、灰度结论与未决项；
   - 在 README「文档分工」登记；
   - `docs/acceptance-p4.md` §7.5 只加一行链接（保持 ≤500 行）。
5. **生产只读复核**：`mem stats --json`、`mem eval flow --profile=prod --db ~/.v2mem/mem.db`（只读）；记录积压曲线与 SLA 结论，不执行生产写操作。
6. **合入与清理**：按 `Base/Gate/Closes` 写 merge 正文；合并后主控在 main 复跑四道门禁；清理 worktree/branch；按 AGENTS 确认 PATH 上 `mem` 来源并询问是否重装。

## Risks & Mitigations

- **自动裁决误写**：`--model-auto` 默认关；只处理本轮 bundle 的 pending；Defer/Conflict 原样保留；每条 decision 带 model_tag；灰度只跑副本。
- **重复裁决/并发**：复用 `ModelAutoCommit` 的 revision CAS 与幂等键；maintain 单实例/租约不变；重跑由 decision 账幂等。
- **eval prod 剖面掩盖真问题**：legacy 判定只认 `bundle_id=''`；新增坏候选仍有 bundle_id，测试强制其变红。
- **scope 写入影响旧值**：UPDATE 只补空；未知值归一为空；不升 schema。
- **maintain 全阶段误删**：`--stage=all` opt-in；GC 沿用现有备份/引用保护；dry-run 全链路零写。
- **命令删除破坏运维**：本轮只删 migrate/batch/candidates；accept/reject 保留；所有删除项在测试中断言替代路径。
- **文档超限**：新验收文档单独成册并登记 README；`acceptance-p4.md` 只加一行。

## Assumptions / Open Items（执行时不再二次询问）

- 用户已确认范围 = 建议 1–5；P4 下一轮。
- 用户已确认受控灰度；子代理不得写生产。
- `accept`/`reject` 最终删除留到“maintain 自动裁决默认开启 + 生产灰度签字”之后。
- 若 Task D 发现吞吐代码缺陷，不在本波修；由主控在波 4 评估是否插入小修复或转入下一轮。
- 如果 `internal/store` 覆盖率跌破 82%，优先补迁移/查询分支测试，不用 `cover-update` 降标。

## Execution Protocol for Subagents

每个子代理必须：

1. 从当前 main 建独立 worktree/branch（`.worktree/<task>`、`dev/<task>`）；所有 bash 命令带 `cd` 前缀。
2. 先写红 case（TDD），再实现；不合并、不推送、不改生产库。
3. 交付五项：红证据、测试尾部、cover 关键行、提交短哈希 + `git diff --stat`、风险/回退口径。
4. 完成后主控按上表顺序合入；合并后清理 worktree 与分支。
